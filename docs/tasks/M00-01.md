# M00-01 — Documentary foundation and repository governance

| Field | Value |
|-------|--------|
| Milestone | M00 |
| Status | READY |
| Dependency | M00-00 (PASS) |
| Type | Local documentation-only modification |

## Objective

Establish the minimal, versionable, coherent documentary foundation for Engineering OS: vision, roadmap, backlog, agent rules, architectural baseline, initial ADR register, and validation framework.

## Rationale

Without explicit documentary contracts and governance, premature implementation lacks acceptance criteria, security gates, and traceability. M00-01 materializes that baseline before technical PoCs.

## Authorized files

1. `README.md`
2. `AGENTS.md`
3. `docs/vision.md`
4. `docs/roadmap.md`
5. `docs/backlog.yaml`
6. `docs/tasks/M00-00.md`
7. `docs/tasks/M00-01.md`
8. `docs/architecture/baseline.md`
9. `docs/adr/README.md`
10. `docs/validation/README.md`

## Exclusions

- Platform implementation.
- Installing or repairing tools/services.
- Node/mise changes.
- ACP execution or real sessions.
- Git writes (commit/push/PR/merge).
- Creating files outside the authorized list.
- Publishing sensitive environment data.

## Acceptance criteria

1. Exactly the ten authorized files exist (created or modified) and no additional product files.
2. README keeps original identity and declares non-operational status.
3. Candidate architecture is presented as provisional.
4. Backlog includes all required M00–M08 tasks, with unique IDs and valid dependencies.
5. Only `M00-00` is `PASS`; `M00-01` is `READY`; all others are `PLANNED`.
6. Initial ADRs appear as proposals/states not falsely marked accepted except ADR-007.
7. Documentation is suitable for a public repository (no secrets or unnecessary sensitive environment details).
8. Local consistency validations are executed and reported.
9. Repository documentation language is English.

## Documentary tests

- `git status --short --untracked-files=all` before and after.
- `git diff --check` and README review.
- Existence check for expected files.
- Relative Markdown link check.
- Backlog ID uniqueness and dependency validation.
- Authorized PASS-state check.
- YAML parser if available without installing dependencies.

## Disclosure risks

Because the repository is **public**, this increment must avoid personal paths, process identifiers, authentication details, private configuration contents, and any data that exposes the environment. M00-00 results are summarized, not dumped.

## Status

`READY` until human approval and integration. This document does not declare the increment integrated or approved by the Owner.

## Manual actions reserved for the owner

1. Review the diff and new files.
2. Selective `git add` of the authorized files.
3. Commit with an appropriate message.
4. Push / PR / merge per their process.
5. Authorize or block moving to M00-02.
