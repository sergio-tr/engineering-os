## Objective

Provide a fail-closed, host-side executable test runner for P1–P8 using rootless Podman, synthetic fixtures, and layered evidence capture. Phase B1 implements the execute path; **this increment does not authorize agents to launch containers**.

## Evidence model (required)

Isolation claims must separate:

1. **Launcher configuration** (`planned_controls`)
2. **Executed argv** (safety scan only; **not** enforcement proof)
3. **Runtime-inspected configuration** (`podman inspect`, read-only)
4. **Behavioral negative-test evidence** (probes, canaries, attributable limit signals)

Argv inspection alone must never produce a PASS for isolation controls.

## Phase B1 hardening (R1–R6)

- R1: Runtime evidence integrity — inspect + behavior required; argv labeled non-proof
- R2: P2–P4 emit container-side `CONTAINER_PATH_KIND`; host canaries; no hard-coded kinds
- R3: P5 requires `executed_denied` for IP and DNS; `unavailable` fails; netns + NetworkMode
- R4: P6 requires attributable memory / PIDs / wall-clock evidence; CPU may be `NOT_TESTED`
- R5: Unique names, best-effort cleanup, presence errors ≠ absence; timeout reaping
- R6: Preserve Podman-only, exact local image, `--pull=never`, triple Owner gate, fixed catalog

## Socket-probe guard fix

- Argv safety scans launcher options and mount sources only (not fixed-catalog workload text).
- P8 may mention `docker.sock` / `podman.sock` paths inside its negative-test script.
- Socket **bind mounts** and privileged/arbitrary mounts remain rejected.
- `--tests P1` constructs only P1 (does not fail on unrelated P8 strings).
- Prior Owner P1 attempt: **BLOCKED** before execution; not a PASS.
