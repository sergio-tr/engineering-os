## Objective

Perform an **independent** verification that Engineering OS external sandbox barriers, evidence, and threat-model coverage are sufficient to close the SANDBOX gate — or document evidence-backed FAIL/BLOCKED with residual risks.

M03-01 PASS is a necessary input, **not** a sufficient condition for SANDBOX PASS.

## SANDBOX gate semantics

| Verdict | Meaning |
|---------|---------|
| NOT_TESTED | No independent gate decision yet (current state) |
| PASS | Independent auditor issues evidence-backed approval; Owner formally accepts |
| FAIL | Material isolation or evidence defect prevents gate closure |
| BLOCKED | Audit cannot complete due to missing authority, environment, or evidence |

Canonical status vocabulary for tasks/gates: `PLANNED`, `READY`, `RUNNING`, `PASS`, `FAIL`, `BLOCKED`, `NOT_TESTED`.

## Audit authority and independence

1. The auditor must **not** be solely the same agent/context that implemented the sandbox runner or authored the PoC execute reports.
2. A separate human Owner review is required before accepting any SANDBOX PASS recommendation.
3. Self-reported runner `PASS` strings are inputs to review, not substitutes for independent analysis.
4. If the only available reviewer is the implementer, the audit remains incomplete: record `BLOCKED` or keep `NOT_TESTED` until independence is satisfied.

## Independent verification methodology

Follow `docs/validation/M03-02-independent-audit.md`.

Summary:

1. Freeze repository SHA and evidence manifest hashes.
2. Review implementation against documented controls (not argv-only).
3. Re-read archived evidence content for consistency, redaction, and false-positive risk.
4. Optionally request **new** Owner-authorized bounded runtime probes only for gaps (never invent PASS from missing tests).
5. Issue written verdict with residual risks and revalidation triggers.
6. Owner accepts or rejects the gate recommendation.

## Acceptance criteria (for M03-02 / SANDBOX PASS)

1. Independence requirement satisfied and documented.
2. Evidence manifest complete and hashes match reviewed files.
3. Every mandatory threat (Owner-defined set; default T1–T12 / N1–N8) is either evidenced or explicitly waived with Owner-accepted residual risk.
4. No unresolved **mandatory** blocker remains.
5. Reproducibility notes for the WSL2 rootless Podman environment are recorded.
6. Live Cursor ACP and real-project access remain unauthorized until after formal SANDBOX PASS acceptance.
7. Final status uses canonical vocabulary; SANDBOX updated only by Owner after audit acceptance.

## Failure / blocked criteria

- Missing or contradictory evidence for a mandatory control → FAIL or BLOCKED.
- Auditor cannot access evidence store or code baseline → BLOCKED.
- Independence unavailable → BLOCKED / NOT_TESTED (do not PASS).
- Attempt to start live ACP or touch real secrets during audit → stop; FAIL process integrity.

## Revalidation triggers

Re-open or regress SANDBOX if any of the following change materially:

- Launcher/assertion security logic
- Podman/cgroup/userns policy
- Image or base OS assumptions
- Evidence format or Owner gate semantics
- Discovery of a false PASS in archived evidence

## Owner approval boundary

- Auditor recommends; **Owner decides** SANDBOX PASS/FAIL/BLOCKED.
- No operational autonomy and no M01-01 live ACP until SANDBOX is PASS and Owner unblocks M01-01 separately.
