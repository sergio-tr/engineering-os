## Contract scope

Four Engineering OS-owned Draft 2020-12 schemas and matching synthetic examples:

- `ProjectProfile`
- `AgentProfile`
- `ExecutionContract`
- `ApprovalContract`

These are not native Paperclip, OpenClaw, ACPX, or Cursor configuration formats.

## Acceptance criteria

1. Only authorized files are created or modified.
2. Schemas declare Draft 2020-12, stable non-network `$id`, `kind`, and `contract_version` `0.1.0`.
3. Examples are synthetic, credential-free, and schema-aligned.
4. Permission matrix distinguishes target policy from current enforcement.
5. ADR-011 exists and remains `RECOMMENDED`.
6. Baseline diagram places the Cursor ACP executor inside an external sandbox boundary.
7. Backlog reconciles `M00-01=PASS`, `M00-02=READY`.
8. `python3 -B scripts/validate_contracts.py` runs successfully for baseline checks.
9. Full JSON Schema validation is reported honestly as PASS or NOT_TESTED.
10. English-only repository policy is respected.

## Validation procedure

1. Inspect Git status before and after edits.
2. Run `python3 -B scripts/validate_contracts.py`.
3. Run `git diff --check`.
4. Verify authorized file list, relative links, backlog IDs/deps/states.
5. Check for secrets and environment disclosures.
6. Do not stage, commit, push, or open a PR from the agent.

## Security limitations

- Contracts and the permission matrix are not runtime enforcement.
- Approvals do not grant technical access by themselves.
- No autonomous execution on real projects before the SANDBOX gate passes.
- Human-only Git integration remains mandatory for MVP.
